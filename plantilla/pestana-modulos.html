Qué es esta herramienta

WebVulnScanner 2.0 es un auditor de seguridad web que revisa un sitio como lo haría un especialista, de forma automática. Trabaja en dos modos:

  • Pasivo (por defecto): observa el sitio como un visitante normal — peticiones HTTP, consultas DNS y lecturas públicas. No ataca nada. Es seguro para cualquier sitio.
  • Activo (solo con autorización expresa del dueño): envía pruebas controladas y no destructivas para confirmar vulnerabilidades reales.

Cada hallazgo se clasifica según OWASP Top 10 2025 y OWASP API Security Top 10 2023, se le asigna su CWE (tipo de debilidad) y un puntaje CVSS v3.1, y los CVE se priorizan con EPSS (probabilidad de explotación) y CISA KEV (explotación real confirmada).

Siempre

🔎 Módulos pasivos

Reconocimiento

IP, servidor, producto y versión que el sitio expone.
Según: cabecera Server, resolución DNS · OWASP A02:2025.

Puertos + banners

Puertos TCP comunes abiertos y el banner del servicio.
Según: lista de puertos de riesgo (21, 23, 3306, 3389, 6379…).

TLS / HTTPS

Versiones de protocolo, cifrados débiles, certificado (validez, clave, firma) y redirección a HTTPS.
Según: SSL Labs / PCI-DSS / RFC 8446 · CVSS · OWASP A04:2025.

Cabeceras HTTP

CSP, HSTS, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy.
Según: OWASP Secure Headers Project · MDN · A02:2025.

DNS y correo

SPF, DMARC, DKIM, BIMI, CAA, DNSSEC y transferencia de zona (AXFR).
Según: RFC 7208 / 7489 / 6376 · RFC 8659 (CAA).

Subdominios (CT)

Subdominios publicados en Certificate Transparency y posibles subdomain takeover.
Según: logs de crt.sh · OWASP A01:2025.

Exposición de archivos

Rutas sensibles accesibles: .git, .env, backups, robots.txt, security.txt.
Según: RFC 9116 (security.txt) · A02:2025.

WAF / CDN

Si hay un cortafuegos o CDN protegiendo el origen.
Según: firmas conocidas (Cloudflare, Akamai, AWS…).

Fingerprint

Tecnologías y versiones: CMS, framework, servidor.
Según: patrones en HTML, cabeceras y meta generator · A03:2025.

WordPress (dirigido)

Si el back es WordPress, sondea sus endpoints: enumeración de usuarios (wp-json, ?author=), xmlrpc.php, versión en readme.html, wp-login y listado de uploads.
Según: endpoints estándar de WordPress · OWASP A07 / A05:2025.

Frameworks / CMS (dirigido)

Según la tecnología detectada, sondea Drupal (CHANGELOG, /user/login), Joomla (/administrator, manifiesto), Laravel (Ignition debug, Telescope) y paneles (phpMyAdmin, Adminer, server-status).
Según: endpoints característicos de cada stack · OWASP A02 / A05 / A07:2025.

Contenido mixto / SRI

Recursos HTTP en páginas HTTPS, scripts externos sin integrity, formularios de contraseña sobre HTTP.
Según: W3C SRI · OWASP A02 / A08:2025.

CSRF (pasivo)

Formularios que ejecutan acciones (POST) sin token anti-CSRF ni SameSite.
Según: OWASP A01:2025 · CWE-352.

Librerías JS (retire.js)

Bibliotecas JavaScript con versiones vulnerables conocidas.
Según: base de datos de retire.js · A03:2025.

Secretos expuestos

Claves de API, tokens y claves privadas filtradas en HTML/JS.
Según: patrones (AWS, Google, Stripe, GitHub, JWT…) · A04:2025.

JWT

Tokens con alg:none, secreto HS256 débil o sin expiración.
Según: RFC 7519 · OWASP A07:2025.

Superficie de API

Documentación OpenAPI/Swagger expuesta e introspección GraphQL abierta.
Según: OWASP API Security Top 10 (API9).

Cloud

Buckets S3/GCS/Azure públicos y referencias a endpoints de metadata.
Según: OWASP A05 / A01 (SSRF).

Correo (MTA-STS / TLS-RPT)

Si el correo del dominio fuerza TLS y reporta fallos.
Según: RFC 8461 (MTA-STS) · RFC 8460 (TLS-RPT).

Supply chain / SBOM

Inventario de componentes (SBOM) y riesgo de dependency confusion.
Según: CycloneDX 1.5 · OWASP A03:2025.

CVE (NVD) + por componente

Vulnerabilidades públicas de CADA componente detectado (servidor, CMS, plugins, librerías), no solo el servidor.
Según: NVD · Wappalyzer → NVD · EPSS (FIRST) y CISA KEV · A03:2025.

TLS profundo (sslyze)

Motor TLS profesional: Heartbleed, ROBOT, CCS-injection, protocolos obsoletos (SSLv2/v3, TLS 1.0/1.1).
Según: sslyze · A02:2025. Opcional (extra enhanced).

Stack extendido (Wappalyzer)

Detecta cientos de tecnologías con versión (CMS, frameworks, DB, librerías) y las correlaciona con CVEs.
Según: Wappalyzer · A03:2025. Opcional (extra enhanced).

Secretos por entropía (detect-secrets)

Además de patrones, detecta cadenas de alta entropía (claves/tokens) que el regex no capta.
Según: detect-secrets (Yelp) · A04:2025. Opcional.
Requiere autorización

🎯 Módulos activos

Solo se ejecutan con el permiso expreso del dueño del sitio (--authorized). Envían pruebas controladas y no destructivas.

Cookies

Flags de seguridad: Secure, HttpOnly, SameSite.
Según: RFC 6265 · OWASP A02:2025.

CORS

Configuración permisiva o que refleja el Origin del atacante.
Según: OWASP A05:2025 · CWE-942.

Inyección

XSS reflejado, SQLi (error y ciega), LFI, SSTI, CRLF y command injection, en parámetros y formularios.
Según: OWASP A05 · CWE-79/89/22/1336/78/93.

Open redirect

Redirecciones a destinos externos controlables por un atacante.
Según: OWASP A01:2025 · CWE-601.

Fuzzing de rutas

Rutas comunes accesibles (admin, backups, paneles).
Según: diccionario corto de rutas.

Control de acceso

IDOR/BOLA (acceso a objetos ajenos) y forced browsing (paneles sin sesión).
Según: OWASP A01:2025 · API1/3/5.

Autenticación

Enumeración de usuarios, credenciales por defecto y ausencia de rate-limit en el login.
Según: OWASP A07:2025 · API2.

SSRF / Host header

SSRF hacia metadata interna, Host Header Injection y cache poisoning.
Según: OWASP A01 · API7 · CWE-918.

Manejo de errores

Stack traces y modo debug expuestos en producción.
Según: OWASP A10:2025 (nueva categoría).

Rate limiting

Ausencia de límite de peticiones (abuso de recursos).
Según: OWASP API Security — API4.

Fuzzing de API (schemathesis)

Si el objetivo expone un OpenAPI/Swagger, genera casos desde el esquema y detecta errores 5xx no manejados, respuestas fuera de contrato y códigos de estado no documentados.
Según: schemathesis · OWASP API Security · A08:2025. Opcional (extra apifuzz).

Herramientas externas

Si están instaladas, delega a motores maduros: nuclei, nmap, WPScan, subfinder, testssl.
Según: sus propias bases (plantillas nuclei, NSE de nmap, WPScan DB).

Cómo se calcula la nota

La nota va de A (excelente) a F (crítico). Parte de 100 puntos y se descuenta por severidad: −25 por hallazgo alto, −10 por medio, −3 por bajo, con una pequeña bonificación por buenas prácticas confirmadas. Un solo hallazgo alto ya baja mucho la nota, por eso refleja el riesgo real, no un promedio.
